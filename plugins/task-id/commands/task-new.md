작업 번호를 새로 발급받는다. **번호를 직접 고르지 말 것.** 조회로 고른 번호는 같은 순간 다른 세션도 고를 수 있다.

## 순서

1. 다음 명령을 실행한다. 인자는 사용자가 준 `<도메인> <이름>` 을 그대로 넘긴다.

   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/claim.js" <도메인> <이름>
   ```

2. 결과는 JSON 한 줄이다.
   - `ok: true` — `id` 가 발급된 번호다. 이 번호로만 파일을 만든다.
   - `ok: false` 이면서 `offline: true` — 원격을 못 봐서 멈춘 것이다. `error` 를 **그대로 전달**한다.
     VPN·git 인증 문제일 가능성이 높다. 번호를 임의로 정해서 진행하지 않는다.
   - `ok: false` 이면서 `pending: true` — push 가 시간 초과로 끝나 원격에 잡혔는지 아직 모른다. `error` 를 그대로 전달하고 멈춘다.
     **그 `id` 로 파일을 만들지 않는다.** 다시 부르면 새 번호가 나오고, 그 번호가 원격에 잡혔으면 `recovered` 로 알려 준다.
   - `ok: false` — `error` 를 사용자에게 알리고 멈춘다.
   - `ok: true` 이면서 `offline: true` — `offlinePolicy` 를 `warn` 으로 둔 저장소다. `warning` 을 그대로 전달하고 진행한다.
   - `ok: true` 이면서 `verified: true` — push 는 시간 초과·오류로 끝났지만 원격에 이 PC 것으로 잡혀 있어 발급한 번호다. 정상 발급과 같다 — `note` 를 한 줄 함께 알린다.
   - `recovered` 가 있는 결과 — 지난번 실패로 보고됐던 번호가 실제로는 이 PC 에 잡혀 있었다. `recoveredNote` 를 그대로 알린다.
     새 번호(`id`)는 그대로 쓴다. 지난 번호를 대신 쓸지는 사용자가 정한다(쓰기로 하면 그 번호로 파일을 만들면 된다 — 훅이 이 PC 번호로 본다).

   - `dryRun: true` — 미리보기다. 선점하지 않았으니 **파일을 만들지 않는다.** `id` 와 근거별 최대값(`max`)만 보고한다.
   - `adopted` 가 있는 결과 — 번호 등록이다(아래). `message` 나 `files` 를 그대로 보고한다. 파일을 새로 만들지 않는다.

3. `path` 가 있으면 그 경로에 파일을 만든다. 없으면 발급된 `id` 로 파일명을 짓는다.

4. 사용자에게 보고할 때 **몇 번을 시도해서 잡았는지**(`attempts`)를 함께 알린다. 2 이상이면 그 사이에 다른 세션이 번호를 채갔다는 뜻이다.

## 옵션 (사용자가 인자로 줬을 때만)

- `--dry-run` — 선점하지 않고 "지금 받으면 나올 번호"만 본다.
- `--adopt <번호>` — 이 PC 에서 쓰던 번호 하나를 원격에 등록한다. 여러 개를 한꺼번에 맞출 때는 `/task-id-sync`.
  원격에 ref 를 만드는 일이라, 사용자가 직접 요청했을 때만 쓴다.
