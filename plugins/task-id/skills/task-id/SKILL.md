# 작업 번호는 조회가 아니라 발급으로 받는다

## 왜

목록을 훑어 빈 번호를 고르는 방식은 **조회와 쓰기 사이에 틈이 있다.** 두 세션이 같은 찰나에 같은 번호를 고르면 둘 다 통과한다. 워크트리를 갈라 병렬로 일하면 옆 세션의 커밋 전 파일은 보이지도 않는다.

## 규칙

1. 번호가 필요하면 `/task-new <도메인> <이름>` 을 쓴다. 목록을 보고 직접 고르지 않는다.
2. 발급은 **원격이 판정한다.** 번호 이름으로 ref(`refs/task-ids/<번호>`)를 만드는데, 깃은 같은 이름의 ref 를 두 번 만들지 못한다. 먼저 만든 쪽만 성공하고, 늦은 쪽은 거절받아 다음 번호로 넘어간다.
3. 거절받는 것은 정상이다. 실패가 아니라 **다른 세션이 먼저 잡았다**는 뜻이다.
4. 원격을 못 볼 때는 경고를 남기고 진행한다. 이때 받은 번호는 **잠정**이라, 나중에 겹치면 바꿔야 할 수 있다.

## 하지 말 것

- 예약 없이 파일부터 만들기 — 훅이 경고한다.
- 거절받은 뒤 같은 번호로 다시 밀기 — 이미 남의 번호다.
- 예약만 해 두고 문서를 안 쓰기 — 번호가 빈다.
