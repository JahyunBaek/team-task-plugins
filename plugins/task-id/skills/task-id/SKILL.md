# 작업 번호는 조회가 아니라 발급으로 받는다

## 왜

목록을 훑어 빈 번호를 고르는 방식은 **조회와 쓰기 사이에 틈이 있다.** 두 세션이 같은 찰나에 같은 번호를 고르면 둘 다 통과한다. 워크트리를 갈라 병렬로 일하면 옆 세션의 커밋 전 파일은 보이지도 않는다. 작업 기록은 대부분 기능 브랜치에서 만들어져서, 다른 브랜치에서 받은 번호도 보이지 않는다.

원격의 ref(`refs/task-ids/*`)가 **번호 등록부**다. 브랜치가 달라도, PC 가 달라도 같은 등록부를 본다.

## 규칙

1. 번호가 필요하면 `/task-new <도메인> <이름>` 을 쓴다. 목록을 보고 직접 고르지 않는다.
2. 발급은 **원격이 판정한다.** 번호 이름으로 ref(`refs/task-ids/<번호>`)를 만드는데, 깃은 같은 이름의 ref 를 두 번 만들지 못한다. 먼저 만든 쪽만 성공하고, 늦은 쪽은 거절받아 다음 번호로 넘어간다.
3. 거절받는 것은 정상이다. 실패가 아니라 **다른 세션이 먼저 잡았다**는 뜻이다.
   거절인지 실패인지는 발급 스크립트가 **원격 상태로** 가린다 — push 가 시간 초과·연결 끊김으로 끝나도 원격에 이 PC 것으로 잡혔으면 발급된다(`verified`).
   끝내 확인하지 못하면 `pending: true` 로 실패한다 — 그 번호로 파일을 만들지 말고 다시 부른다(지난 번호가 잡혀 있었으면 `recovered` 로 알려 준다).
4. 원격을 못 보면 **번호가 나오지 않는다.** 다른 PC 가 무엇을 잡았는지 모르는 상태라 그렇다.
   VPN 과 git 인증을 확인하고 다시 부른다. 번호를 임의로 정해 진행하지 않는다.
   (설정에서 `offlinePolicy` 를 `warn` 으로 둔 저장소에서만 잠정 번호가 나오고, 그 번호는 나중에 겹치면 바꿔야 한다.)
5. 등록부에 없는 번호(플러그인을 쓰기 전에 만든 번호, 플러그인 없이 만든 번호)는 `/task-id-sync` 로 등록한다.
   원격의 모든 브랜치, 이 PC 의 로컬 브랜치, 커밋 전 문서까지 본다. 기본은 조회만 하고, 등록은 사용자 승인 뒤 `--apply`.
   같은 번호에 다른 문서가 있다고 나오면 그대로 알린다 — 번호를 바꿀지는 사람이 정한다.

## 훅이 경고했을 때

훅은 **새로 만든** 작업 기록 파일만 보고, 막지 않고 알리기만 한다. 경고를 보면 바로 고친다.

- **"는 이미 있습니다"** — 같은 번호의 다른 문서가 있다. `/task-new` 로 번호를 다시 받고 파일 이름을 바꾼다.
- **"폴더는 … 인데 번호의 도메인은 …"** — 둘을 맞춘다. 보통 폴더를 번호의 도메인에 맞춘다.
- **"원격에 이미 등록된 번호입니다"** — 다른 세션·PC·브랜치에서 받은 번호다. `/task-new` 로 다시 받고 파일 이름을 바꾼다.
- **"이 PC 의 git 사용자가 원격에 잡은 번호인데 이 PC 발급 기록에는 없습니다"** — 발급이 실패로 보고됐지만 실제로는 잡혔던 이 사용자의 번호일 수 있다.
  그 번호를 계속 쓸지 사용자에게 묻고, 쓰기로 하면 `/task-new --adopt <번호>` 로 기록에 올린다(원격 ref 작성자가 지금 `user.email` 과 같을 때만 올라간다).
- **"선점하지 않고 새 작업 기록을 만들었습니다"** — 목록에서 고른 번호다. `/task-new` 로 다시 받는다.

## 하지 말 것

- 선점 없이 파일부터 만들기 — 훅이 경고한다. (이미 저장소에 있는 문서를 고치는 것은 경고하지 않는다.)
- 거절받은 뒤 같은 번호로 다시 밀기 — 이미 남의 번호다.
- 선점만 해 두고 문서를 안 쓰기 — 번호가 빈다.

## ref 정리

`refs/task-ids/*` 는 저절로 지워지지 않는다. `/task-id-prune` 으로 정리한다.

6. 정리는 **파일이 기준 브랜치에 커밋된 번호만** 지운다. 지우기 전에 그룹마다 바닥 표시(`refs/task-ids/_floor/<번호>`)를 먼저 세운다. 파일이 아직 원격에 없는 번호의 ref 를 지우면 그 번호가 다시 풀려 다른 PC 의 초안과 겹친다.
7. 기본은 조회만 한다. `--apply` 를 붙이기 전에 **무엇을 지우는지 보여 주고 승인을 받는다.** 원격 ref 삭제는 되돌릴 수 없다.
